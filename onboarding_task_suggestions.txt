Onboarding Task Suggestions — One per Work Profile Area

1. Geospatial semantic embedding (multimodal)
Take a small sample of the project's geospatial data (imagery + text/metadata pairs) and build a minimal pipeline that embeds both modalities into a shared vector space using an existing pretrained model (e.g., CLIP-style), then sanity-check retrieval (query by text, get back the right image tile or vice versa).

2. Document extraction and knowledge integration
Pick a handful of representative source documents, extract entities/relations with the project's current extraction tool (or a baseline like spaCy/LLM-based extraction), and map the results onto the existing ontology/knowledge graph schema to find where the schema is missing coverage.

3. Domain adaptation/fine-tuning and model optimization
Fine-tune (or LoRA-tune) a small base model on a narrow slice of in-domain data and compare its outputs against the base model on a handful of held-out examples, to establish a baseline adaptation workflow.

4. Model merging research
Reproduce a basic SLERP or DARE-TIES merge between two checkpoints (e.g., a base model and a fine-tuned variant) using an existing library (e.g., mergekit), and evaluate the merged model against both parents on a small task set.

5. Benchmarking and metrics
Stand up a lightweight evaluation harness that computes precision/F1 for the extraction pipeline on a labeled sample set, so there's a repeatable metric to compare future extraction/merging changes against.

6. Sustainability-inclusive evaluation
Instrument one existing training or inference run with energy/carbon tracking (e.g., codecarbon or experiment-impact-tracker) and report compute-cost vs. accuracy tradeoffs as a baseline for future efficiency targets.

Task 1 Detail: Geospatial semantic embedding (multimodal)

The idea is to build a small end-to-end proof-of-concept that embeds geospatial imagery and its associated text/metadata into a shared vector space, so you can search across modalities (e.g., find an image tile by describing it in text, or vice versa).

Why this task first: It's a good onboarding task because it's self-contained, doesn't require deep familiarity with the rest of the codebase yet, and forces you to touch the actual geospatial data the project works with early on.

Suggested steps:
1. Get a sample dataset. Pull a small subset of the project's geospatial data — satellite/aerial imagery tiles paired with descriptive text or metadata (captions, location names, land-use tags, etc.).
2. Pick a pretrained multimodal model. Start with something off-the-shelf rather than training from scratch — CLIP, or a remote-sensing-specific variant if one exists (e.g., RemoteCLIP, GeoCLIP, SkyCLIP) tend to perform much better on satellite imagery than generic CLIP.
3. Embed both modalities. Run the image encoder over your image tiles and the text encoder over the paired metadata/captions, producing vectors in the same space.
4. Build a tiny retrieval index. Store the embeddings (a flat numpy array or FAISS index is enough at this scale).
5. Sanity-check retrieval. Query with a text description ("flooded agricultural field") and confirm the nearest image embeddings make sense — and the reverse (image to nearest text).
6. Write up findings. Note where retrieval fails (e.g., ambiguous terrain, rare classes) — this becomes useful signal for whether the project needs a domain-adapted encoder rather than a generic one (ties into Task 3).

Deliverable: a short script/notebook plus a few example queries with results, plus notes on embedding quality and any domain gaps observed.
